# Seams review of main, 2026-11-24

The first run of the `seams` skill (`cross-slice-coherence S6`). It reviews `main` at its joins, not
one PR: where two areas solve one problem two ways, where a stage's output is not what the next one
reads, and what nobody owns. Each finding proposes a disposition. This report filed nothing and changed nothing; the KAN-38
owner filed two of the proposed issues afterwards (see *Proposed Jira issues*).

## What was reviewed

- **Code:** `origin/main` at `de4a121`, after #46 to #49 merged. This is the first run, so all of
  `main` was reviewed, not a range.
- **Commands run:**
  - `git grep` over `src` and `scripts` for `start_run(`, `set_experiment(`, `slice/`,
    `rev-parse`, and the fakes' method signatures;
  - `python scripts/audit_open_questions.py` (from `cross-slice-coherence S8`, which this branch
    builds on);
  - the allowlists in `tests/test_conventions.py`, to separate known from new.
- **Read:** each `src/primer/<area>/interface.py`, `src/primer/serving/book.py`,
  `src/primer/evaluation/fakes.py` and `golden.py`, and `docs/plans/autonomous-loops.md`.

## Findings

### Same problem, two or more solutions

- **N1. Six ways to read the commit** — *known*.
  - The copies: `drawing/evaluate.py:472` (`_git_state`, the shared one), `evaluation/golden.py:78`,
    `speech/evaluate.py:263`, `story/grid.py:109`, `illustration/consistency/experiment.py:274`, and
    `data/versioning.py:40`.
  - The shared one is `SHARED_GIT`; the golden, speech, story and illustration copies are the four
    `GIT_ALLOWED` entries, each with a key. The sixth is deliberately out of scope: it records a
    dataset's commit, not a run's.
  - *Disposition:* `cross-slice-coherence S2`, once the helper's home is decided. The plan's Open
    question goes to the repository owner.
- **N2. Four ways to log an MLflow run** — *known*.
  - The four: `drawing/tracking.py` (`log_run`), `speech/train.py:134` (`log_run`),
    `story/grid.py:73` (`MlflowLogger`), and `illustration/consistency/experiment.py:346`
    (`log_to_mlflow`).
  - The other three are allowlisted in `START_RUN_ALLOWED`, with KAN-128, KAN-39 and KAN-103;
    `tracking.py` is the shared logger (`SHARED_LOGGER`).
  - `tracking.py` is drawing-only (`STAGE = "drawing"`), so the fix is to generalise it, not copy it.
  - *Disposition:* create one cross-area Jira issue, "Generalise drawing/tracking.py into a shared
    run logger", linked to KAN-128, decided by the speech, story and illustration owners. This is
    the plan's existing Open question. Filed afterwards as KAN-131.
- **N3. Three names for one slice metric, and two copies of the function** — *new*.
  - The convention in `docs/engineering/model-development.md` is `slice/<key>/<value>/<metric>`.
    `drawing/tracking.py:43` and `speech/train.py:131` follow it.
  - `slice_metric_name` already exists twice: `drawing/tracking.py:41` makes the key, value and
    metric safe through `metric_part` and raises on an empty part, and `speech/train.py:128` is
    its own copy. The character set it allows is the same, but it cleans only the value, not the
    key or the metric, and has no empty-part check. The same inputs can give different names.
  - `illustration/consistency/experiment.py:368` writes `slice/<key>:<value>/<metric>`. The doc
    records that MLflow rejects `:` in metric names on Windows clients, so this site fails for any
    member logging from Windows.
  - `story/grid.py:124` writes `slice/<key>_<value>/<metric>`. That runs the key and value
    together: `source_african_storybook` and `age_3` cannot be split back into a key and a value
    (story's slice keys are `source` and `age`, `story/slices.py`). Its docstring at
    `:119` still says `slice/<key>=<value>/...`, which the code no longer writes.
  - The `cross-slice-coherence S1` scans do not see metric names.
  - *Disposition:* include it in N2's issue, because promoting `drawing/tracking.py`'s
    `slice_metric_name` and deleting speech's copy removes all three names and the extra copy.
    If N2 waits, open two small issues, one for illustration (KAN-103) and one for story (KAN-39),
    since the illustration one is a Windows failure today.
- **N4. The seven-tag set is written out by hand five times** — *new*.
  - The copies are the tag dicts in `drawing/tracking.py`, `speech/train.py`,
    `illustration/consistency/experiment.py`, and twice in `story/grid.py` (`:228` and `:341`).
  - Coverage differs. `cross-slice-coherence S1` reads two literals and checks all seven tags in each (speech,
    illustration). Drawing's `run_tags` is the shared logger, covered by
    `tests/drawing/test_tracking.py`. Story's two (`:228` and `:341`) are handed to `MlflowLogger`
    as a parameter, so S1 does not see them (`primer/story/grid.py` is in `TAGS_UNCHECKED`);
    `tests/story/test_grid.py` asserts the tags for both runs. Adding an eighth required tag still
    means editing five places.
  - *Disposition:* with N2. The shared logger owns the tag set.

### A stage's output is not what the next stage reads

- **The serving chain is consistent.** `serving/book.py` composes the area contracts, and
  `tests/models/test_area_interfaces.py::test_serving_builds_a_complete_fake_book` covers it. Renaming
  a field fails it (checked during the 2026-11-24 prep). No finding.
- **N5. The golden runner composes its own fakes, which do not match the contracts** — *known per
  stage, not coordinated*.
  - Recorded in pieces: drawing in `mvp-cloud-deploy` (`:420` and `:1268`: `top5(true_label)` is
    handed the answer), story in `story-generation-llm` (`:403`: that plan's S5 adds an adapter so a real
    writer can run in the golden set). No plan records the seam as a whole.
  - `evaluation/fakes.py:27` `top5(true_label)` is handed the answer, where the contract is
    `drawing.interface.analyse(image)`.
  - `fakes.py:45` `write(prompt, target_words, age)`, where the contract is
    `story.interface.write(request: StoryRequest)`.
  - `fakes.py:79` `flagged(prompt, expect_flagged)` takes the ground truth.
  - So no real area can run through `golden.py`, and the gate's numbers on fakes say nothing about
    the real composition.
  - *Disposition:* narrow `cross-slice-coherence S7` to this seam, as the prep recommended (the
    owner dropped it instead, in favour of the issue below). Create a Jira issue under the golden
    runner's key (KAN-89) for one cross-stage decision that starts from
    `story-generation-llm` S5's adapter and says whether drawing and the other stages use the same approach, or the
    fakes are rewritten onto the contracts. Without it, two owners can build two fixes.
