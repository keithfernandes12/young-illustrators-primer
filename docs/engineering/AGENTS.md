# docs/engineering

How the team works: processes and checklists that people and agents follow.

- `documentation.md` — which document goes where, frontmatter, file names, plan rules.
- `engineering-loop.md` — the path from request to merged PR.
- `review-checklist.md` — what every review checks, and the finding categories.
- `ci.md` — what CI runs, what blocks a merge, and the rules for tests, red builds, flaky tests
  and changing CI.
- `type: engineering`; `status: active` or `deprecated`. Change these by PR like code; they are
  owned in `.github/CODEOWNERS`.
